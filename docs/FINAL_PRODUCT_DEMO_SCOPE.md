# Final Product Demo Scope

This document defines the visual-only product-completion demo requested for ElectroCMS.

## Purpose

Create a complete, high-fidelity interface prototype of the finished ElectroCMS product so the UI/UX can be iterated before every planned subsystem is production-ready.

This demo is **not** evidence that planned features are implemented. Every future-facing surface must remain visually identifiable as demo/modelled/planned where relevant.

## Primary no-code-builder anatomy

Desktop uses a stable professional builder composition:

1. Top global command bar.
2. Left rail + Insert/Elements Library.
3. Dominant visual canvas.
4. Right contextual Inspector.
5. Optional bottom status/context bar.

The experience should feel familiar to users of professional visual builders while retaining original ElectroCMS identity, terminology and layout.

## Visual principles

- High-density professional UI; compact, not cramped.
- Minimal/Swiss clarity + data-dense SaaS ergonomics.
- 4px micro-grid, 8px primary rhythm.
- Canvas is always the dominant surface in visual-authoring mode.
- Persistent Insert Library and Inspector on wide desktop.
- Routine edits do not require modals.
- Clear selected/hover/focus/disabled/demo/planned states.
- Accessible labels and visible keyboard focus.
- Responsive drawers/sheets on narrower layouts.
- No decorative gradients or excessive glass effects as the default editor language.

## Demo status language

Use explicit badges when a surface is not production behavior:

- `Demo` — interactive presentation-only behavior.
- `Modelled` — canonical contracts exist but full runtime is not complete.
- `Planned` — final-product capability represented visually only.

No demo control may be used as evidence to mark a functional phase complete.
