# ElectroCMS React — Single Bento Density UI Contract

Status: **PERMANENT APPLICATION UI CONTRACT**

## 1. One application theme

ElectroCMS uses exactly one UI/UX theme for the editor application: **Bento Density**.

- Do not add application theme presets.
- Do not add light/dark application modes.
- Do not add alternate visual skins such as glassmorphism, minimal, developer console, material, monochrome, etc.
- `ProjectThemeControls` remain valid because they configure the frontend/backend output generated by ElectroCMS; they are not application UI themes.

## 2. Visual character

Bento Density combines:

- high information density;
- modular Bento surfaces;
- dark graphite application chrome;
- teal primary accent and restrained violet secondary accent;
- compact professional controls;
- rounded cards with restrained elevation;
- strong hierarchy without dashboard-card clutter;
- canvas-first authoring.

## 3. Layout rules

### Desktop

- Floating Bento top bar.
- Resizable primary workspace rail, left or right.
- Every navigation item always has an icon; expanded rail shows icon + label, collapsed rail shows icon.
- Builder layout: Insert Library → Canvas → Inspector.
- Canvas receives the largest available area.
- Layers is contextual/floating rather than permanently consuming canvas width.

### Tablet

- Insert Library becomes a horizontal strip above the canvas.
- Inspector narrows before stacking.
- Navigation uses the compact drawer below 960px.

### Mobile

- 44px minimum touch targets.
- Navigation opens as an animated modal drawer.
- Insert Library remains horizontally scrollable.
- Canvas remains the primary viewport.
- Inspector becomes a bounded bottom panel instead of reducing canvas width.
- Command toolbar remains reachable through horizontal scrolling; do not hide selection commands.

## 4. Interaction rules

- Buttons must expose hover, active, disabled and keyboard-focus states.
- Menu and toolbar icons animate subtly on hover/press.
- Active navigation icons may use restrained pulse emphasis.
- Popovers/drawers use short entrance animations.
- Respect `prefers-reduced-motion` globally.
- Do not animate SVG path geometry directly; animate the SVG/wrapper transform.

## 5. Accessibility

- Visible `:focus-visible` treatment is mandatory.
- Text metadata floor: 10px; normal compact controls: 11px+.
- Mobile interactive floor: 44px.
- Color cannot be the only indicator of active/error/success state.
- Preserve semantic roles, labels, tab states and keyboard navigation.
- Maintain horizontal/vertical overflow containment to avoid root-page overflow.

## 6. Canvas rules

- Neutral dark stage with subtle grid/dot reference.
- Rendered document remains visually distinct from application chrome.
- Canvas pan/scroll/zoom must remain usable at desktop, tablet and mobile widths.
- Inspector is a Bento dock on desktop and bounded lower panel on mobile.
- Layers retains canonical selection, rename, lock/hide and reorder commands.
- Do not create parallel canvas/document state.

## 7. React implementation rules

- Preserve Domain → Application → Infrastructure → Presentation.
- Use canonical project/document state and existing commands.
- Prefer semantic CSS variables over one-off colors.
- Keep static configuration outside render functions when practical.
- Do not add a component framework merely for styling; existing React + Tailwind v4 + semantic CSS is the foundation.
- Every UI refactor must keep lint, typecheck, unit, coverage, build and Playwright green.

## 8. External design references

Use contemporary professional editor patterns as inspiration without copying:

- Webflow: canvas dominance, left navigation/add surfaces, right contextual properties, canvas controls.
- Figma: reduced chrome and work taking center stage.
- Framer: familiar visual canvas, responsive layout and compact canvas controls.

The resulting ElectroCMS UI must remain visually distinct and internally consistent.
